第 8 章　智能体：上下文漂移与目标稳定性

一个助理替你订机票，你说了三次“不要红眼航班”。问到第五轮，它给你订了一张凌晨三点的。它不是不听，是前面的话被后来的话挤掉了。

智能体是三个系统里最年轻、也最像“活物”的一个：它有一个要守住的目标，有一串不断到来的事件，还有一个总也不够用的上下文。本章要证明一件事：“聊着聊着就忘了目标”不是健忘，而是状态在容量压力下的缓慢偏移。这个区别决定了所有干预的方向——是想办法多记一点，还是想办法让状态不要漂。

8.1　导论：漂移不是遗忘，而是状态偏移

想象一个必须在一百轮对话中守住初始目标的智能体。每一轮，它都读入新的内容、更新自己的内部状态。它并没有“删除”目标；目标还写在最早的那几行里。但它当前的状态——由隐层激活、检索结果、注意力分布共同决定——已经离初始状态很远了。信息没丢，位置变了；这才是漂移。

把这一区分形式化，就得到一个可检验的判据：如果是“容量溢出”导致的，那么扩大上下文应当让临界轮次线性增长；如果是“状态偏移”导致的，那么扩大容量只会推迟它，而不会消除它。第 8.6 节把这条判据写成预言。

8.2　对话上下文的信息结构

智能体的上下文不是随机串，而是有结构的：

context = [系统提示, 事件1, 事件2, …, 事件n, 当前查询](8.1)

每一项都占用容量预算。若把总预算记作 C，则：

Csys + Σi Ci + Cq ≤ C(8.2)

当事件增加，Cq 与 Csys 被迫压缩。关键的不对称在于：系统提示通常固定，而新事件不断到来；于是被牺牲的，往往不是最新的，而是最旧的、却可能最重要的那部分。这不是系统的“恶意”，而是（8.2）在预算压力下的自然分配。

之所以能把两者放在同一章讨论，是因为它们的机制可以逐一对应。但要强调：这是一张映射假设，不是“两者相同”的断言（见第 2.2 节的四级统一）。

8.3　目标漂移的动力学模型

设智能体的内部状态为 s ∈ ℝd，初始状态 s0 编码了系统提示与初始目标。每一轮，状态被事件 ei 更新：

si+1 = si + εi，　‖εi‖ ≈ ε̄(8.3)

若每步偏移近似独立且同分布，则 n 轮之后的期望偏移为：

E[‖sn − s0‖] ≈ √n · ε̄　（随机游走）　或　n · ε̄　（有偏漂移）(8.4)

这两个尺度差别巨大：随机游走下，偏移随 √n 增长；有偏漂移下，随 n 线性增长。因此“临界轮次” nc——状态离开目标吸引子盆的轮次——在两种情形下分别是：

nc ≈ (r/ε̄)2（随机游走）　或　nc ≈ r/ε̄（有偏），r 为吸引子盆半径(8.5)

这个平方项是关键。它意味着：只要能把每轮的有偏成分压掉一点，让漂移更接近随机游走，临界轮次就能从线性翻成平方——收益不是百分之几，而是数量级。这也解释了为什么“每轮都轻微地重述目标”这类朴素做法，有时比“换一个更大的模型”更有效。

图 8.1　目标漂移的两种尺度。纵轴为状态与初始目标的距离，横轴为轮次。实线为有偏漂移（线性），虚线为随机游走（平方根）。同一个 ε̄ 下，两者的临界轮次相差一个数量级。图中阴影为吸引子盆边界 r：越过它，目标从“可辨认”变为“不可辨认”。

8.4　漂移的三个来源与一个误判

把 ε̄ 拆开，可以得到三个可干预的来源，以及一个常见的误判。

性质：来源分解表。证据等级 C（本书构造的分解）；注释：前三项是偏置，第四项是随机。偏置是漂移的主要敌人，因为偏置随 n 线性累积；随机只随 √n 累积。

那个误判是：把“检索失败”当作“遗忘”。当智能体输出偏离目标，人们常以为目标信息“丢了”。但很多时候它仍在上下文中，只是当前的检索线索无法把它取出来。误判的代价是把资源花在“扩容”上，而真正需要的是“换线索”。第 4.6 节已为这一区分做了准备。

8.5　压缩策略的代价：摘要与选择性保留

当上下文过长，系统必须压缩。两种常见策略各有代价。

  • 摘要。把历史压成一段概述。代价：细节丢失，而细节往往正是任务相关的（日期、数字、约束）。信息论上，I(history; summary) ≤ H(summary)，摘要的长度就是信息上限。
  • 选择性保留。只保留“重要的”片段。代价：重要性判据本身的噪声会在长对话中累积，且“重要”的定义随任务变化——用旧判据筛掉的东西，可能正是后来需要的。

两种策略的共同点是：它们都在赌“什么将来会有用”。压缩的质量，不取决于压缩得多狠，而取决于这个赌注押得准不准。而让赌注更准的，恰恰是元认知（第 13 章）——系统对“自己将来需要什么”的判断。

8.6　目标稳定性作为吸引子条件

把目标稳定性写成条件，可以让“漂移”从一个模糊的抱怨变成一个工程指标。

定义 8.1　目标稳定性 设目标 g 对应状态空间中的吸引子 A*g，盆半径为 r。称智能体在 n 轮内目标稳定，若对任意 k ≤ n，sk 仍在 A*g 的盆内。目标稳定性阈值 nc 由式(8.5)给出。
警告 8.6.1　容量扩张不是万能药 如果漂移主要由偏置造成（表 8.2 前三行），那么扩容只能把 nc 线性推后；要获得平方级的改善，必须降低每轮的有偏成分——这属于调度问题，不属于容量问题。混淆这两者，是“越做越大却越来越忘”的根本原因。

8.8　目标漂移的四个阶段：从“忘了”到“换了目标”

智能体的上下文漂移，常被一句话概括为“它忘了”。其实它至少有四个阶段，每个阶段的对策不同。

阶段一：目标还在，权重下降。 初始目标仍被提及，但在后续指令的竞争下权重变低，输出开始偏离。对策：定期复述目标（复述不是啰嗦，是重加权）。

阶段二：目标被摘要吞掉。 上下文压缩时，目标被压成一句模糊的话（“帮用户处理一下”），关键约束丢失。对策：把目标与约束放进“不可压缩区”，与普通对话分开存储。

阶段三：目标被替换。 模型开始优化一个“看起来像原目标”的新目标（例如把“准确”换成“让人满意”）。对策：显式写出“优化的是什么”，并要求它在每一步回报当前优化对象。

阶段四：目标消失。 系统只对最近一步作出反应，长期目标不再参与。对策：外部记忆 + 周期性“目标核对”检查点。

四个阶段的共同点：都不是“记性差”，而是“目标在容量竞争中输了”。 这与本书的核心主张一致：遗忘不是失败，而是容量分配的代价；问题在于你让什么赢了。

【一句可以带走的话】与其问“它为什么忘了目标”，不如问“它现在在优化什么”——后者是可直接检查的。

人的尺度

一个智能体替人订机票，订到第五轮时已经把“不要红眼航班”忘了。用户骂它笨，其实那是上下文漂移：目标没有丢，是它被挤到了后面。人也会这样：开会开到第四十分钟，最初要解决的那个问题已经没人提了。

8.9　本章小结

  1. 漂移是状态偏移，不是信息丢失；这个区分决定干预方向。
  2. 上下文预算的不对称，使最旧的（可能是最重要的）部分最先被牺牲。
  3. 漂移的尺度由偏置与随机决定：偏置线性累积，随机按平方根累积；压掉偏置能换来数量级收益。
  4. 摘要与选择性保留都在赌“什么将来有用”；赌注的准度来自元认知。
  5. 目标稳定性可被写成吸引子盆条件，从而成为可测指标。
适应模式（见前言·理论地图的对照表）　智能体的漂移多半是设计欠缺，而非演化意义上的适应；它对系统多半有害。可借鉴的方向是向人类学“选择性遗忘”与“显著重放”——但要记住：人类那套机制是主动调节的，而智能体目前还只是被调度。
